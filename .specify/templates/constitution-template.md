## 项目开发约束

- 后端固定使用 Python 3.11、FastAPI 和 Pydantic v2，源码直接位于仓库根目录。
- 前端固定使用 React 19、TypeScript 和 Vite，源码位于 `ai-agent-frontend/`。
- 所有开发必须先经过 Speckit 的规格、计划、任务和实现流程；任务完成后必须更新任务状态。
- 代码和文档中的说明使用中文；代码注释必须说明必要的设计原因，避免无信息注释。
- 新增技术或依赖时，技术文档必须说明它解决的问题、引入原因、版本和验证方式。
- 保持实现简洁，禁止为了尚未提出的需求堆叠代码或拆分服务。

## 核心原则

### 一、接口优先与可独立验收

每项用户可见能力必须先形成特性规格，明确用户价值、边界场景、
可量化验收标准和责任人。实现必须拆分为可独立开发、测试、演示和交付的
纵向切片。实现完成前，必须先定义带类型的输入与输出结构。实施计划必须将
需求映射到源码路径、测试、契约和运维事项；任务必须按依赖顺序排列，并能
追溯到用户故事。

理由：小而可验证的交付切片能够降低重构风险，避免实现细节意外变成产品契约。

### 二、契约优先与稳定流式协议

所有对外 HTTP API 必须纳入 OpenAPI，并通过契约测试验证。JSON 字段必须使用
`snake_case`，时间必须使用 UTC RFC 3339，错误必须使用稳定的机器可读错误码，
业务 ID 必须由服务端生成。破坏兼容性的变更必须启用新 API 版本，或提供经过
批准的迁移方案。

流式接口必须遵循版本化 SSE 契约：消息体使用 POST 提交；首个事件为 `meta`；
`seq` 严格递增；所有事件携带一致的 `request_id` 和 `run_id`；按约定发送
心跳；每条流只能有一个 `done` 或 `error` 终态事件。密钥、原始提示词、
内部堆栈和隐藏思维链不得发送给客户端。前端必须忽略未知事件字段，并且不得
假设分片边界等于字符、单词或句子边界。

理由：明确的契约使 React 客户端、API、模型供应商和后续版本能够独立演进，
同时避免静默的协议回归。

### 三、默认安全的数据与工具边界

安全控制必须默认启用，并且不能依赖模型是否服从提示。密钥必须来自环境变量
或密钥管理服务，禁止提交到仓库、打包到前端、写入日志或链路追踪、通过错误
响应返回。使用 Cookie 身份的写请求必须校验 CSRF Token 和允许的 Origin；
CORS 必须使用明确的来源白名单。

文件、下载、网页抓取和终端工具必须实施结构校验、超时、大小限制、路径约束、
软链接检查、SSRF 与私网地址拦截、重定向限制和可审计白名单。终端工具必须
默认关闭，禁止把不可信输入拼接成 Shell 命令。每次智能体运行必须使用隔离的
工作目录和工具预算。模型输出必须视为不可信输入，Markdown 和 URL 在渲染前
必须净化。

理由：AI 智能体会把不可信文本转化为高权限动作，因此安全执行点必须位于模型
之外，并且能够被测试和审计。

### 四、软件测试、契约测试与 AI 评测不可省略

每项用户可见行为、API/SSE 契约、安全边界、持久化规则和失败路径都必须有测试。
P0 行为和所有安全控制必须自动化覆盖。默认测试禁止调用真实第三方服务，必须
使用替身、模拟或固定录制数据。适用时至少包含单元测试、契约测试、集成测试、
安全测试和浏览器端到端测试。

模型、提示词、Embedding、检索或工具选择发生变化时，必须运行版本化 AI 评测集，
记录模型参数、数据集版本、延迟、Token、成本和质量指标。修改评测基线前，
必须按文档规定比例进行人工复核。

理由：编译成功无法证明对话质量、流式协议和安全性；软件测试与可重复 AI 评测
共同构成发布门禁。

### 五、可观测、可重试且执行有界

每个请求和智能体运行必须具有关联 ID。服务必须输出结构化且脱敏的日志，并记录
请求延迟、模型调用、Token、成本、工具调用、错误、取消、排队时间和数据库健康
指标。API 到模型、API 到工具的关键链路应启用分布式追踪。日志不得包含密钥或
非必要的个人内容。

可能因重试而重复创建消息、运行、工具调用或生成物的写操作必须支持幂等。
模型供应商、MCP 服务和工具必须设置明确超时、有限重试与退避、取消处理和可查询
终态。健康检查必须区分进程存活与依赖就绪。

理由：流式连接和外部 AI 依赖具有复杂失败模式，系统必须支持安全恢复和快速诊断。

### 六、模块化单体与克制设计

默认架构为一个可部署的 Python API，并按 API、会话、智能体、工具、RAG、
供应商适配、持久化和可观测性划分模块；MCP 服务可以独立部署。API 处理器禁止
直接调用模型 SDK 或执行零散数据库查询；领域行为必须通过带类型的应用服务和
供应商接口提供。

新增基础设施、抽象层或独立服务时，实施计划必须给出具体需求、可量化风险或容量
边界。依赖必须锁定版本，升级必须经过评审、测试和 AI 评测。功能设计必须采用
满足契约与安全要求的最小方案，禁止过早拆分微服务或增加推测性封装。

理由：清晰模块边界保证可替换性，克制的架构保证系统易于理解、部署和维护。

## 附加约束

### 技术基线

- 后端：Python 3.11、FastAPI、Pydantic v2、SQLAlchemy 2、Alembic。
- 前端：React 19、TypeScript、Vite、React Router。
- AI 编排：默认使用 LangGraph；如采用其他状态机方案，计划必须记录理由和取舍。
- 存储：PostgreSQL + pgvector 保存持久数据和向量；Redis 保存限流、取消标记、
  短期锁和临时协调状态；生成物存入兼容 S3 的对象存储。
- 集成：Qwen/DashScope 必须经供应商适配接口接入；MCP 服务使用 Python MCP SDK
  或 FastMCP；本地和测试环境使用 Docker Compose。
- 质量工具：Ruff、静态类型检查器、Pytest、ESLint、TypeScript 检查、Vitest、
  Playwright，以及依赖和镜像漏洞扫描。

### 数据、隐私与兼容性

- 业务时间必须使用 UTC，业务 ID 必须由服务端使用 UUIDv7 或 ULID 生成。
- 涉及用户内容或生成物的特性规格必须说明数据分级、保留、删除、导出和备份规则。
- 首版无需兼容 Java/Spring 内部类和 Kryo 文件。迁移旧数据必须作为独立特性，
  并具备回滚和核对机制。
- 商业发布前必须确认源码、图片、字体、提示词和知识文档的许可证与使用权。

### 性能与用户体验

- 默认目标：SSE `meta` 事件 P95 小于 500 毫秒；固定模型和网络基线下，
  首个文本分片 P95 小于 3 秒。
- 系统必须支持至少 50 条并发流持续 5 分钟，不得发生跨会话串流、连接泄漏或
  无界内存增长。
- React 界面必须支持桌面端和 390 像素移动端，支持键盘操作、清晰焦点、
  WCAG AA 对比度、取消、重试、刷新恢复和安全 Markdown。文字与控件不得重叠
  或横向溢出。

### 特性必需产物

适用时，`specs/` 下的特性目录必须包含 `spec.md`、`plan.md`、
`research.md`、`data-model.md`、`quickstart.md`、`contracts/` 和
`tasks.md`。API 变更必须更新 OpenAPI；流式变更必须提供 SSE 事件示例和
JSON Schema；持久化变更必须提供 Alembic 迁移；用户可见变更必须提供自动化
测试方案。

## 开发流程

1. **规格化**：编写用户故事、边界场景、功能需求、非功能与安全需求、假设和
   可量化结果。
2. **规划**：记录技术上下文、模块边界、数据模型、契约、依赖、性能目标和
   宪章检查结果。
3. **任务化**：按用户故事生成依赖有序的任务。每个任务必须标明准确路径，以及
   所需的单元、契约、集成、安全、界面或 AI 评测工作。
4. **实现**：先完成基础阶段，再实现用户故事。测试和契约必须与行为变更同步。
   禁止通过削弱断言绕过失败的质量门禁。
5. **评审**：设计完成后和发布前必须重新执行宪章检查。评审必须覆盖安全边界、
   数据所有权、错误处理、可观测性、迁移、回滚和文档。
6. **发布**：只有验收测试通过、必要日志与指标已存在、文档已更新、产物中无密钥，
   且未解决风险已由责任人明确接受时，特性才算完成。

## 治理

本宪章是项目最高优先级的开发规范。特性规格、计划、任务、实现或部署方式与本宪章
冲突时，必须在实现前解决；确实无法遵守时，必须在计划的“复杂度跟踪”表中记录
责任人、失效条件、已考虑的更安全替代方案和批准结论。

修订宪章必须同时评审本文件和 `.specify/memory/constitution.md`，并包含：

- 修订原因及其对现有规格、计划、任务和运行行为的影响；
- 已同步更新的模板，或明确说明无需修改下游模板；
- 规则变化所需的迁移或兼容性说明；
- 活跃宪章顶部的同步影响报告；
- 语义化治理版本号：删除原则或不兼容变更升级主版本；新增原则或实质扩充义务
  升级次版本；澄清、措辞和错别字修正升级修订版本。

每次特性评审必须核对活跃宪章版本并记录例外。例外必须有期限、由技术负责人批准，
并创建后续任务。每次发布以及 API/SSE 契约、数据分级、模型供应商、工具权限或
部署拓扑变化时，必须复审本宪章。
